## 🔴 高危修复

### 1. Master 故障转移后任务静默丢失
- 原缺陷：Worker 回调地址用分发包固定 MasterAddress（旧 Master 挂后回调死地址）；默认 ExecutionTimeoutMinutes=0 无超时兜底；新 Master 收到旧在途回调（无 TraceId 记录）直接忽略 → 结果永久丢失、失败不重试
- 修复：
  - `Options/SchedulerOptions.cs`：`ExecutionTimeoutMinutes` 默认 **0 → 10**
  - `Execution/JobExecutionController.cs`：回调前读 Redis `MasterInfoKey` 解析**当前 Master 地址**（失败回退分发地址）；回调 **3 次指数退避重试**（500ms/1s/2s）
  - `Scheduling/JobResultHandler.cs`：孤儿回调**不再静默丢弃**——Redis SETNX 幂等守卫（`findx:scheduler:result:{TraceId}`，TTL 10min）后，成功回报幂等落库、失败回报读 DB `TryCount` 续跑重试/死信（`RecoverOrphanFailureAsync`）

### 2. 默认零鉴权（RCE + 状态伪造面）
- 原缺陷：`execute`/`result` 接口在 `ClusterToken` 留空（默认）时完全放行——内网任意 POST 可触发任意已注册 IJob 执行、可伪造结果回报污染状态
- 修复：`SchedulerModule.cs` 启动校验——启用调度端或执行端而 `ClusterToken` 为空 → 抛 `InvalidOperationException`（fail-fast）

### 3. 失败重试覆盖周期锚点 → cron 节奏永久偏移
- 原缺陷：分发失败后 `ApplyFailureAsync` 把 `NextRunTime` 改写为退避时刻，覆盖 CAS 已推进的下一正常周期 → 重试成功后任务永远偏移一个周期
- 修复：
  - `Models/ScheduledJob.cs`：新增 **`RetryAtTime`** 列（重试时刻，与周期锚点解耦）
  - `Storage/ScheduledJobStorage.cs`：`GetDueJobsAsync` 双条件（NextRunTime 或 RetryAtTime 到期）；新增 `ClaimRetryAsync` CAS（仅清 RetryAtTime）；`ApplyFailureAsync/ResetSuccessAsync/ApplyDeadLetterAsync` 读写 RetryAtTime
  - `Scheduling/DistributedScheduler.cs`：扫描双分支——重试到期（`R:` period 前缀）优先于周期到期

## 行为变更（部署必读）

1. **必须配置 `Findx:Scheduler:ClusterToken`**，否则启用调度/执行端的节点启动即抛异常
2. 默认开启 **10 分钟在途超时兜底**（原 0=关闭；显式设 0 可关闭）
3. Worker 注册表从逐节点 String key 改为 Hash 索引；`WorkerKeyPrefix` 字段保留兼容但不再用于注册
4. 组件为全新交付，无存量数据迁移问题；新增 `RetryAtTime` 列随 `scheduler_job` 表自动建列
